# Decisions log

Format: date, decision, reason. Newest at the bottom.

1. **2026-09-29: SQLite for local dev and tests; Postgres in docker-compose only.** The build machine has no Docker and no Postgres. Models avoid Postgres-only features; where Postgres matters (partial unique index for one open downtime per machine) the index is declared with `postgresql_where` and `sqlite_where`, both supported by SQLAlchemy.
2. **2026-09-29: Python 3.13, managed with uv.** Satisfies "3.11+". uv gives a lockfile and fast installs.
3. **2026-09-29: Access token sent as a Bearer header, held in memory on the client; only the refresh token lives in an httpOnly cookie.** This keeps normal API calls immune to CSRF. The cookie-based endpoints (`/auth/refresh`, `/auth/logout`) are protected by a double-submit CSRF token (`fp_csrf` cookie echoed in the `X-CSRF-Token` header) plus `SameSite=Strict`.
4. **2026-09-29: Fixed role set, not a roles table with editable permissions.** Roles are an enum (`operator`, `supervisor`, `technician`, `inspector`, `storekeeper`, `manager`, `admin`) stored in `user_roles`. The spec's roles are fixed and permissions are checked in code; a `roles` table would add nothing until custom roles are needed.
5. **2026-09-29: In-process rate limiter.** A sliding-window limiter keyed by IP + identity for auth and ingest. It resets on restart and does not work across multiple workers; swap for Redis if the app is scaled horizontally. PIN brute force is also bounded by a persistent per-user failed-attempt lockout column.
6. **2026-09-29: No `make` on the Windows build machine.** The Makefile is still the documented interface (works on Linux/macOS/CI); README lists the equivalent raw commands.
7. **2026-09-29: PIN login requires a registered shop-floor device.** A 4-digit PIN alone is too weak for internet-facing login. A supervisor registers a phone/tablet once (`POST /devices`), which stores an opaque device token in the browser; PIN login needs that token, and only users assigned to the device's site can sign in on it. Revoking the device also invalidates its sessions at the next refresh.
8. **2026-09-29: `If-Match` is honoured but optional.** Editable records return an `ETag`; if the client sends `If-Match` and it is stale, the API answers 412. Making it mandatory (428) would break simple integrations and CSV tooling for little gain.
9. **2026-09-29: Only admins see every site implicitly.** Everyone else, managers included, sees the sites they are assigned to (`user_sites`). Multi-plant managers are assigned to every plant. This keeps one rule instead of role-specific exceptions.
10. **2026-09-29: Organization settings live in a JSON column (`organizations.settings`) validated by the `OrgSettings` Pydantic model**, not a key/value `settings` table. New settings need a default in code, not a migration.
11. **2026-09-29: A user's PIN length is stored (`users.pin_length`) so the PIN pad submits on the last digit.** This removes a confirm tap for operators. It reveals only the length, which barely narrows the search space; the device requirement and 5-try lockout carry the security.
12. **2026-09-29: The operator app auto-locks by signing out after `operator_idle_lock_min` (default 10) minutes of inactivity**, then preselects the last user on the PIN screen for a quick unlock. The session otherwise lasts through the shift thanks to the refresh cookie.
